# Prediction Site

## ⚡ Как запустить и пользоваться (быстрый старт)

1. **Запусти проект:** `docker compose up -d --build` (нужен только Docker).
2. **Открой:** лента — <http://localhost:8080>, админка — <http://localhost:8080/admin.html>.
3. В админке слева — меню разделов. Работай так:
   - **🔑 Ключи Gemini** — вставь Gemini API-ключ(и) ([взять тут](https://aistudio.google.com/apikey)). Без них ИИ-события не генерятся.
   - **🖼 Картинки** — вставь ключ Cloudflare (Account ID + Token) для картинок; без него работает бесплатный Pollinations. Зелёный чип = кто реально генерит сейчас.
   - **⚙ Настройки генерации** — нажми **▶ Старт**, чтобы включить ИИ-генерацию событий из новостей (и сразу выпустить). Тут же источники, критерии важности, промты, лимиты.
   - **🔴 Лайв-каналы** — **отдельная** кнопка Вкл/Выкл для самостоятельных (не-ИИ) прогнозов по котировкам Binance. Чекбокс «Все категории» включает все каналы.
   - **⏱ Сроки категорий** — на сколько вперёд ставить срок по каждой теме.
   - **🏢 Логотипы** — клик по логотипу = заменить (5 вариантов)/удалить; можно создать новый; подсказки берут слова из ответов.
4. **Смотри результат** на ленте — события появляются сами; можно ничего больше не трогать.

## Стек
- **Бэкенд:** PHP 8.2 — встроенный веб-сервер `php -S` + фоновый воркер (отдельный процесс)
- **Фронтенд:** ванильные JavaScript / HTML / CSS (без фреймворков и сборки)
- **Данные:** JSON-файлы в `data/` (без внешней БД)
- **Картинки:** расширение GD (перекодирование в WebP) + Cloudflare Workers AI / Pollinations
- **Внешние API:** Google Gemini (текст), Cloudflare Workers AI (картинки), Binance (котировки), Google News RSS (новости)
- **Упаковка:** Docker + Docker Compose
- **Тесты:** PHPUnit 11 (юнит + интеграционные)

## Быстрый старт

Нужен только **Docker** (Docker Desktop или Docker Engine).

```sh
docker compose up -d --build
```

Открыть:
- Лента: <http://localhost:8080>
- Админка: <http://localhost:8080/admin.html>

Остановить:
```sh
docker compose down
```

Ключей для старта не требуется: без ключей Gemini новости не генерятся, но сайт открывается;
ключи вводятся в админке. Картинки без ключей идут через Pollinations (бесплатно, без ключа).

## Архитектура: два процесса

Контейнер по `start.sh` запускает **два процесса**:

```
start.sh
 ├─ php generator/worker.php   (фон)  — каждые ~10с дёргает «тики»
 └─ php -S 0.0.0.0:8080        (веб)  — отдаёт страницы и API
```

**Воркер** (`worker.php`) — простой цикл: раз в ~10 секунд ходит по HTTP на свой же сервер и вызывает:
- `generate.php?action=tick` — авто-генерация рыночных событий по расписаниям;
- `news.php?action=news_tick` — сбор новостей + генерация событий из них.

Веб-сервер `php -S` **однопоточный** — важное следствие: тяжёлые операции (запрос к Gemini)
блокируют сервер на время выполнения. Поэтому внутри кода self-HTTP вызовы заменены на прямые
вызовы функций, где это критично.

## Ветка 1: новости → события (AI)

Точка входа — `news.php?action=news_tick` (или кнопки в админке). Шаги:

1. **Сбор (`fetch_source` / `news_fetch_do`).**
   Для каждого источника из `config.sources` (тема или RSS-ссылка) тянется **свежий** Google News RSS
   (`https://news.google.com/rss/search?q=…&hl=ru`). Новые заголовки (дедуп по хешу link+title)
   складываются в `data/news.json` со статусом `new` и датой публикации `pubDate`. Пул ограничен
   `config.news_keep`. Непереработанные новости **старше 7 дней** помечаются `skipped` (не постим протухшее).
   При отборе (шаг 3) предпочтение отдаётся **свежим** (последние 3 дня); если свежих мало —
   берутся из накопленного пула («кеша»), чтобы всегда было из чего постить. Сроки события всегда
   в будущем (см. шаг 4), даже если новость чуть постарше.

2. **Оценка важности (`gemini_rank`).**
   ВСЕ новые заголовки одним запросом отправляются в Gemini. По тексту `config.rank_prompt`
   («Критерии важности») модель ставит каждому балл **1–10**, приписывает **категорию** и причину.
   Мусор с низким баллом отбрасывается. Возвращается топ `config.rank_keep`.
   В промт заложено требование **разнообразия тем** (максимум 1–2 из одной категории).

3. **Ротация по категориям (`run_ranked_generation`).**
   Генерация идёт строго **по кругу по категориям главной страницы**. Указатель
   `config.gen_cat_rr` каждый прогон переходит к следующей категории и берёт из неё самую важную
   новость. Если по категории новостей нет — переходит к следующей. Так темы не повторяются.
   - Обход идёт по **ИИ-категориям** (`ai_cats()` = категории с `type:'ai'`) — это ровно те, что
     показываются на вкладках главной страницы (Экономика, Геополитика, Война, Технологии, Политика,
     Крипто-новости и т.д.).
   - **Код-категории** (`type:'code'` — Крипта, Акции, Валюты, Индексы, Металлы, Сырьё, Битвы, Гонки)
     в этот обход **не входят**: их события генерируются отдельно из шаблонов по котировкам Binance
     (см. «Ветка 2»), а не из новостей.
   - Категория события **жёстко фиксируется** категорией ротации: выбранная новость кладётся именно
     в текущую категорию обхода (`news_to_event_do($item, $forceCat)` → `build_event_from_ai`), а не
     та, что модель проставит сама во втором запросе. Это гарантирует чёткий обход всех вкладок.

   > Соответствие «категории генерации ↔ вкладки главной»: набор `ai_cats()` в `generate.php` совпадает
   > с не-код категориями в `TAB_DEFS` (`assets/app.js`). Добавляешь свою ИИ-категорию в админке — она
   > автоматически попадает в обход; чтобы она была отдельной вкладкой на главной, добавь её в `TAB_DEFS`.

4. **Формирование события (`gemini_generate` → `build_event_from_ai`).**
   Выбранная новость уходит в Gemini вторым запросом с промтом `build_event_prompt`. Модель
   возвращает строгий JSON:
   ```json
   {"question":"…","type":"open|closed","options":["…"],
    "category":"код","timeframe":"1d|1w|1M…","resolve_date":"ГГГГ-ММ-ДД|пусто",
    "image_en":"short English scene"}
   ```
   - **type=closed** → строго **ДА/НЕТ**, ровно два исхода. Если модель добавит третий вариант
     или вернёт «Да/Нет/…» — лишнее отбрасывается, остаётся ДА/НЕТ (`build_event_from_ai`).
   - **type=open** → **до N вариантов** (N = `config.market_options`, это ПОТОЛОК, а не точное число:
     может быть 2, 3… сколько реально осмысленных исходов). Варианты — либо числовые диапазоны
     («ниже 90», «90–95», «выше 100» — для цен/курсов/ставок), либо взаимоисключающие исходы.
   - **Картинка под каждый вариант** — только для **смысловых** ответов (например «Да, останется у
     поста», «Нет, уволят», «Партия N»): модель возвращает `options_en` (англ. сцена под каждый такой
     вариант по ключевым словам вопроса), и лента рисует своё фото на каждый (через `img.php`, WebP-кэш).
   - Для **числовых** вариантов и диапазонов («выше 100», «90–95», «менее 30%», «1-2 / 3-4 / 5+»)
     картинки **НЕ** генерируются — только текст (`is_numeric_answer`).
   - **Единообразие**: в одном вопросе либо картинки у ВСЕХ вариантов, либо ни у кого. Если все
     варианты числовые — картинок нет; если есть хоть один смысловой — картинка у каждого.
   - **срок:** если в новости есть конкретная дата — берётся она; иначе `timeframe` зажимается в
     диапазон категории из `config.cat_timeframe` (см. `cat_tf_range`).
   - **image_en** — англ. описание сцены для генерации картинки (ключевые слова вопроса буквально,
     без подмены бюрократией, без лишних флагов, лицо — только если человек назван в вопросе).
   - Если в тексте есть название компании (`company_logo_for`) — на карточку ставится готовый логотип.

5. **Сохранение.** Готовое событие кладётся в начало `data/events.json` (лимит `MAX_EVENTS=500`),
   новость помечается `used`. Снимок отбора пишется в `data/rank.json` (для дашборда админки).

## Ветка 2: рынки (шаблоны, Binance)

Точка входа — `generate.php?action=tick` (расписания) или `?action=generate` (вручную).
Это **код-категории** (`type: code`): крипта, акции, валюты, индексы, металлы, сырьё, «битвы», «гонки».

- Цены берутся из Binance (`data-api.binance.vision`), кэш 30 сек в `data/prices.json`
  (`crypto_prices` / `asset_price`).
- Типы рыночных событий: `updown` (выше/ниже текущей цены), `range` (диапазоны цены),
  `versus` (битва двух активов), `race` (гонка нескольких). Число вариантов — `config.market_options`.
- **Расписания** (`data/schedules.json`, секция «Лайв-каналы» в админке): каждый канал —
  «Лайв {категория} · {интервал}» с частотой выпуска. При пере-сидировании существующие
  активность/интервал/счётчик сохраняются.

## Ключи и модели Gemini

Функция `gemini_fallback($prompt, $kind)` — сердце устойчивости:

- **Несколько ключей** (`config.gemini_keys`) = несколько Google-аккаунтов. Работают **по кругу**
  (`config.key_rr`): каждый вызов начинается со следующего ключа → суммарный дневной лимит удваивается/утраивается.
- **Кулдаун**: ключ с лимитом пропускается ~70 сек, с ошибкой ~600 сек; если все «отдыхают» —
  пробуются всё равно.
- **Несколько моделей** (`config.gemini_models`), от бесплатной к платной: `flash-lite` → `flash` → `pro`.
  Первая рабочая используется, остальные — запасные при её лимите.
- Статусы пишутся в `config.model_status` / `config.key_status` (🟢 ok / 🔴 limit|error) и
  показываются чипами в админке. Технические ошибки переводятся в понятный текст (`human_error`).
- Реальный расход (запросы/токены) считается в `data/usage.json` по тихоокеанскому дню
  (как сбрасывается лимит Google).

## Генерация картинок

Картинка карточки выбирается в `app.js → headImg(e)` по приоритету:
**логотип компании → фото по `image_en` → цветной бейдж категории**.

Фото запрашивается у `generator/img.php?q=<сцена>&w=&seed=` — это **кэширующий WebP-прокси**:

1. Считает ключ кэша (провайдер + промт + размер + seed) и смотрит `data/genimg/w_*.webp`.
   Если есть — отдаёт мгновенно, никуда не ходит.
2. Если нет — генерит через `imglib.php`:
   - **Цепочка провайдеров** (`img_provider_chain`): активный → другие с ключами → **Pollinations**
     (крайний запасной, без ключа). Если весь сервис недоступен — переход к следующему.
   - **Ротация ключей внутри провайдера** (`img_generate_raw`): несколько ключей на провайдера,
     упавший помечается (кулдаун: лимит 120с, ошибка 600с) и пропускается, берётся следующий.
     Статусы — в `data/img_keys.json`.
   - Успешный результат перекодируется в **WebP** (`img_to_webp`, GD) и кладётся в кэш.
3. Если все сервисы легли — `502`, и на странице срабатывает фолбэк на бейдж (`onerror`).

Провайдеры:

| Провайдер | Ключ | Лимит |
|---|---|---|
| **Cloudflare Workers AI** | Account ID + API Token (можно несколько аккаунтов) | ~10 000 neurons/сутки на аккаунт, сброс ежедневно (~сотня картинок flux-schnell) |
| **Pollinations** | не нужен | ограничение по частоте (крайний запасной) |

Промт стиля картинок — общий для всех провайдеров (`config.img_prompt`, `{q}` = сцена).
Каждая картинка генерится **один раз** и дальше отдаётся из кэша.

## Авто-закрытие событий

`generate.php → resolve_due()` закрывает **рыночные** события, у которых вышел срок: берёт реальную
цену с Binance и проставляет итог (ДА/НЕТ, финальная цена). Вызывается на тиках. Событие получает
`result` и подсвечивается в ленте как завершённое.

## HTTP API

**`generator/generate.php`** (рынки/лента):

| action | назначение |
|---|---|
| `list` | список событий (JSON) |
| `meta` | категории + подсказки таймфреймов (для админки) |
| `generate` | ручная генерация (preset или category+type+timeframe+count) |
| `tick` | авто-генерация по расписаниям (воркер) |
| `resolve` | закрыть просроченные рыночные события |
| `clear` | очистить все события |
| `img_gen` | тест генерации картинки (через провайдера) |
| `img_usage_get` | счётчик картинок за день |
| `cat_list` / `cat_add` / `cat_del` | пользовательские категории |
| `sched_update` | правка расписаний «Лайв-каналов» |

**`generator/news.php`** (новости/конфиг/ключи):

| action | назначение |
|---|---|
| `news_fetch` / `news_list` / `news_del` / `news_clear` | пул новостей |
| `news_to_event` | превратить одну новость в событие |
| `news_tick` | авто-проход (воркер): собрать + оценить + сгенерировать |
| `rank_now` | прогнать отбор важности сейчас |
| `config_get` / `config_save` | чтение/запись настроек |
| `key_add` / `key_del` / `keys_reset` | ключи Gemini |
| `img_key_add` / `img_key_del` / `img_keys_reset` / `img_status_get` | ключи и статусы провайдеров картинок |

**`generator/img.php`** — не JSON, а кэширующий прокси картинок (отдаёт WebP или `502`).

## Конфигурация (`data/config.json`)

Основные поля (дефолты задаются в `cfg()`):

| Поле | Смысл |
|---|---|
| `gemini_keys[]`, `gemini_models[]` | ключи и модели Gemini (по кругу, с фолбэком) |
| `sources[]` | источники новостей (темы или RSS) |
| `rank_prompt` | критерии важности (промт отбора) |
| `gen_prompt` | правила формулировки вопроса |
| `img_prompt` | шаблон стиля картинок (`{q}` = сцена) |
| `auto{active,interval,per_run,auto_publish}` | авто-поток новостей |
| `rank_keep`, `news_keep`, `rpd_limit` | размеры пулов и лимит-счётчик |
| `feed_per_cat` | сколько прогнозов на категорию в ленте |

## Админка

`http://localhost:8080/admin.html` — боковое меню, каждая секция отдельно:

- **⚙ Настройки генерации** — кнопка **Старт/Стоп** только для **ИИ-генерации из новостей**
  (`config.auto.active`: собирает новости → делает события). Источники, критерии важности, правила
  генерации, настройки авто-потока, дашборд отбора.
- **🔑 Ключи Gemini** — ключи и модели (клик по чипу = выбрать; 🟢 активный, 🔴 лимит/ошибка).
- **⏱ Сроки категорий** — диапазоны сроков для ИИ-категорий.
- **🔴 Лайв-каналы** — **отдельный** переключатель **Вкл/Выкл** самостоятельных (НЕ-ИИ) прогнозов
  — рынки/лайв по котировкам (`config.live_active`, независим от ИИ-кнопки; при включении сразу
  запускает генерацию). Чекбокс **«Все категории»** — вкл/выкл сразу все каналы. Ниже — сами каналы
  (частота, число прогнозов). Лайв-событие генерится при **live_active ON И канал активен**.
- **🖼 Картинки** — провайдер, ключи (несколько, с фолбэком), промт, тест генерации.
- **🏢 Логотипы** — управление логотипами, которые сайт подставляет на карточки. **Клик по логотипу**
  → модалка: удалить / сгенерировать **5 вариантов** и выбрать замену. Поле **«Создать логотип»** —
  новый по названию. Блок **подсказок** предлагает слова из ответов событий (напр. «Пшеница», «Зерно»),
  для которых логотипа ещё нет. Матчинг — данными: `data/logos/_manifest.json` (имя→файл) +
  `data/logos/_keywords.json` (имя→ключевые слова для авто-подстановки). Генерация — через тех же
  провайдеров картинок (Cloudflare/Pollinations), с фолбэком.
- **🛠 Ручная генерация** — разовая генерация рыночного события.
- **➕ Категории** — свои категории.

## Тесты

```sh
./run-tests.sh
```

Собирает образ, ставит зависимости, гоняет PHPUnit. Текущее: **36 тестов, 113 проверок**.

| Файл | Тип | Что проверяет |
|---|---|---|
| `tests/HelpersTest.php` | юнит | разбор сроков, категории, `human_error`, бейджи, отсутствие ложных лого |
| `tests/ImageProviderTest.php` | юнит | нормализация ключей, порядок фолбэка (`img_provider_chain`), конвертация в WebP |
| `tests/ApiIntegrationTest.php` | интеграционный | HTTP-эндпоинты (`list`/`meta`/`config_get`/`news_list`), round-trip конфига, добавление/удаление ключей, `502` без ключей |

Юнит-тесты не ходят в сеть. Интеграционные поднимают **отдельный** php-сервер со своей временной
папкой данных (`PS_DATA_DIR`) — реальные `data/` и ключи **не трогаются**, внешние API не вызываются.
